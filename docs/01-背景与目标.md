# 01 · 背景与目标

## 这个项目要回答什么

Intel Core Ultra 一代起把 NPU（Intel AI Boost）塞进了消费级笔记本。
它跑得动什么、跑不动什么、什么条件下才值得用 —— 这些问题的公开答案大多停留在
"NPU 有 XX TOPS"的规格表层面。本项目用**项目自身要跑的真实负载**去量：

1. **LLM 自回归解码**（Qwen2.5-1.5B INT4）放 NPU 值不值？
2. **编码器前向**（ModernBERT-150M）在 NPU 上比 CPU/iGPU 快多少？前提条件是什么？
3. **JEV-lite**（typed decision engine，一次前向回答任意类型化问题）能不能整体搬到 NPU？

## 为什么是 JEV-lite

JEV-lite 是本项目自带的模型：它把 **每个候选标签写进输入序列**（`<<l>>` 标记），
head 只是一个 `Linear(768,1)` 在这些位置上读值，softmax 在每个问题自己的标签集内做。
好处是 schema 是**推理时的数据**、不是权重里的常量 —— 换问题、换标签、换整个 workflow
都不用重训。代价是 head 必须能按位置 gather，这也正是它在 NPU 上必须拆图的原因。

模型质量（本次整理时从 `output/results/` 复算）：

| 配置 | accuracy | ECE |
|---|---|---|
| 集成（w=0.50 + 锐化） | **0.7005** | **0.0288** |
| 冻结探针 | 0.6695 | 0.0384 |
| 微调模型 | 0.6490 | 0.0769 |
| TypeSafe Jev 1.13.0（引用值） | 0.7270 | 0.1440 |

即：准确率落后商业 Jev 约 0.027，但**校准好 5 倍** —— 对"按置信度自动路由、
把不确定的丢给人"这种用法，校准比那 0.03 准确率更重要。

## 边界（不做什么）

- **不训练新模型**。本次整理不重跑 `02_train.py`（T4 上约 25 分钟，且不是整理任务的目标）。
- **不追求 SOTA**，也不与商业 Jev 做同条件比较：Jev 的 0.727 是零样本成绩，
  而本项目模型在 1,016 条同分布样本上训练过（这个框架对 Jev 更不利，是准确的说法）。
- **不外发**。仓库只在本地建 git，不推远端；日志里的本机路径已遮蔽。
- **不删原始证据**。19 个原始结果文件全部保留，重跑结果另存 `output/results/rerun/`。

## 验收标准

1. `python -m pytest` 全绿（不需要 NPU 即可跑）。
2. `run.ps1 check` 能确认设备、模型、算例就位。
3. 三条主要结论各有一个脚本能重跑，且重跑结果自带溯源字段。
4. 不覆盖任何原始结果文件；权重指纹等**新增的核对结论**要在文档里写明。
5. `git status` 干净，有可追溯的提交历史。
