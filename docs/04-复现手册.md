# 04 · 复现手册

从零把环境重建到"能重跑三条结论"的每一步。设项目根为 `$P`（默认 `G:\npu-decision-engine`）。

## 0. 前置条件

| 项 | 要求 | 检查 |
|---|---|---|
| OS | Windows 10/11（脚本用 PowerShell；Python 部分跨平台） | `$PSVersionTable` |
| Python | 3.10+（本机 3.14.6） | `python -V` |
| NPU | Intel Core Ultra + 驱动（本机 `Intel(R) AI Boost`） | `.\run.ps1 check` |
| 磁盘 | ≥ 22 GB 空闲（模型 5.4 GB + ONNX 3.6 GB + 缓存 4.8 GB） | — |

**NPU 不是必需的**：`pytest`、`probe/*`、`bench_*` 的 `CPU` 路径都能在没有 NPU 的机器上跑。

## 1. 依赖

```powershell
cd $P
python -m pip install -r requirements.txt
```

## 2. 自检

```powershell
.\run.ps1 check
```

它会打印：Python 版本、OpenVINO 版本与可用设备、设备名、模型/数据集/ONNX 产物的在位情况。
设备列表里应出现 `NPU`（若没有，先装 Intel NPU 驱动；`ov_props.py` 可看详情）。

## 3. 取大件（`.gitignore` 排除的三类）

```powershell
python src/fetch/dl-data.py       # data/typed-decisions（~2 MB，10 个 parquet）
python src/fetch/dl_1_5b.py       # models/Qwen2.5-1.5B-Instruct-int4-ov（~893 MB）
python src/fetch/dl_7b.py         # 可选，4.3 GB
```

`models/ModernBERT-base/`（含 `onnx/model_q4.onnx`）需要从 HuggingFace 获取：

```powershell
python -c "from huggingface_hub import snapshot_download as d; d('answerdotai/ModernBERT-base', local_dir=r'models\ModernBERT-base')"
# 编码器基准还需要 INT4 导出：
python -c "from huggingface_hub import hf_hub_download as d; d('answerdotai/ModernBERT-base','onnx/model_q4.onnx',local_dir=r'models\ModernBERT-base')"
```

需要代理时用环境变量（**不要改脚本**）：

```powershell
$env:HF_PROXY = "http://127.0.0.1:<你的代理端口>"
# 例：Clash 默认 7890/7897；按你自己的代理软件填
```

## 4. ONNX 与检查点

`output/onnx/` 里的产物**已随仓库保留在本地**（不入 git）。若从零重建：

```powershell
# 训练（GPU，T4 上约 25 分钟；本机 RTX 5060 亦可）
python engine/02_train.py --epochs 20
# 标定 → 评估 → 集成
python engine/03_calibrate.py
python engine/04_eval.py
python engine/07_ensemble.py
# 导出 ONNX（整图 + 侧车权重）
python engine/06_export_onnx.py --quantize
```

导出后**务必**做两件事：

```powershell
.\run.ps1 fingerprint        # ONNX 权重 vs 检查点，确认同源
python src/bench/bench_jev.py --mode verify    # 输出侧再确认一次
```

> 为什么必做：2026-09 那批 ONNX 与本项目当前的 `jevlite.pt` **并不同源**（已证实）。
> 不核对就会重演"NPU 数字到底跑在哪份权重上"的糊涂账。详见
> [docs/03-约束与踩坑.md](03-约束与踩坑.md#5-onnx-产物与当前检查点不同源已证实)。

## 5. 跑测试与三条结论

```powershell
.\run.ps1 test                 # 23 项，无需 NPU，约 2 秒

# 结论线 1：LLM 解码（慢，NPU 上每轮数十秒；建议先只跑 latency 模式）
python src/bench/bench_llm.py --mode latency

# 结论线 2：编码器形状与设备（约 8 分钟，其中 NPU 编译占大头）
python src/bench/bench_encoder.py --mode static
python src/bench/bench_encoder.py --mode scaling

# 结论线 3：JEV 整图 vs 拆图
python src/bench/bench_jev.py --mode full
python src/bench/bench_jev.py --mode hybrid
```

结果默认写到 `output/results/rerun/`，自带 `generated_by`/`generated_at`/`openvino`/`host`。
**原始结果在 `output/results/` 不会被覆盖**——两边对照着看，差异本身就是证据。

## 6. 期望值（与 2026-09-22 原始结果对照）

| 项目 | 原始值 | 重跑期望 |
|---|---|---|
| NPU 编码器 静态 L=128 | 38.39 ms | 同量级（±20%，受驱动与温度影响） |
| NPU 编码器 L=768 | 253.27 ms | 同量级 |
| NPU 整图（JEV） | 编译失败 | ❌ 现在表现为**段错误**（0xC0000005），不是可捕获的编译异常 |
| NPU 编码器 + CPU head | 189.18 ms | ❌ **不可复现**：NPU 编译该图段错误（见 docs/03 第 9 节） |
| NPU LLM 吞吐 | 3.6–10.6 tok/s | 定性慢于 CPU；具体倍数会漂（见 docs/02 第五节） |

**不要期待复现到小数点。** 本机实测同一配置跨月重跑的偏差可达 20–50%（驱动更新、
NPU TURBO 的伪影、提前 EOS 等）。判定标准是**方向与量级**，不是末位数字。

## 7. 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| **脚本零输出、退出码 -1073741819** | NPU 编译该图时段错误（0xC0000005，见 [docs/03 第 9 节](03-约束与踩坑.md#9-npu-编译-jev-图会直接段错误2026-10-环境回归)） | 该调用放子进程（`harness.run_isolated_device`）；JEV 的 NPU 路径目前走不通 |
| `run.ps1` 报"无法将 Do-Test 识别为 cmdlet" | `.ps1` 存成了 UTF-8 **无 BOM**，PS 5.1 按 GBK 解码破坏了中文注释 | 用 UTF-8 with BOM 重新保存（`tests/test_project_hygiene.py` 已守住） |
| `pwsh` 找不到 | 本机只有 Windows PowerShell 5.1 | 用 `powershell -File .\run.ps1` |
| `NPU` 不在设备列表 | 驱动未装/被禁用 | 装 Intel NPU 驱动；`python src/probe/ov_props.py` 看详情 |
| NPU 编译报 `IsNaN` 不支持 | 图里有 masked-softmax 痕迹 | 拆图（`--mode hybrid`），见 docs/03 第 2–3 节 |
| NPU 编译报形状错误 | 动态形状 | 先 `reshape` 成静态，见 docs/03 第 1 节 |
| 首次 NPU 编译要 30+ 秒 | NPU 编译器在优化图 | 正常；可用 `CACHE_DIR` 缓存（收益不明显） |
| `Invalid usage ... externally stored data` | `.onnx.data` 改名/挪走 | 成对改名并修内部 `location`，见 output/onnx/README.md |
| 打印中文乱码或 `UnicodeEncodeError` | 系统代码页不是 UTF-8 | `src/paths.py` 已自动重设 stdout；仍乱码则 `chcp 65001` |
| 数据集加载走 HF 缓存 | 离线 | 正常回落，不是错误 |
